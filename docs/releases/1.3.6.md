## Corrections

- `2026-11-22`: The first Observatory-only activation trial (`10:34:01Z`–`10:34:06Z`) automatically rolled back because the check inspected the index before startup had finished. The activation guard now verifies the running executable SHA and waits for the index before checking the EXPLAIN plan; the retry succeeded at `10:50:40Z`.
- `2026-11-22`: The first postcheck run stopped before external probes because the verifier required a JSON Content-Type on native 1.2.8 `/readyz`, which returns valid JSON without that header. A later feed assertion also assumed raw URLs in standard/best feeds must be subsets of `trackers_all`; each eligibility tier selects a canonical URL independently. The verifier was corrected to parse native readiness JSON and check the actual feed count/format/protocol-partition contracts. Final verification passed at `2026-11-22T11:12:13Z`.

## Limits

- IP-search performance was measured before the Web cutover using a 20-request S1 loopback sample on standby port 8082: 27.932 ms median / 35.703 ms p95, all HTTP 200. The earlier 1.3.5 standby sample was 2,888.044/3,454.319 ms for the same IP query. This is a strong short-sample improvement, not a sustained-load or global network benchmark.
- No endurance, long-duration capacity or third-party tracker-list admission claim is made.
- No public embedded assets changed; the existing `?v=1.3.5` keys remain intentional and their origin/public hashes matched after cutover.
