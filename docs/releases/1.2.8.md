# Tracker Observatory 1.2.8

## Status

Promoted.

## Scope

- Reduce native Tracker hot-path allocation and lookup costs in HTTP query parsing and peer selection. Defer the endpoint hash index for small swarms.
- Build inputs include the workspace version, the seven matching lockfile entries, HTTP parsing and wire tests, the swarm engine and its tests, and two performance examples.
- The UDP wire format, HTTP query and reply rules, registry limits and web assets are unchanged. No database migration is required. The native service restart resets its in-memory registry.
- Changelog and test scope. [Changelog](../../CHANGELOG.md#128--native-tracker-efficiency) · [Isolated performance comparisons](../capacity/tracker-hotpath-2026-11-18.md)

## Promotion

- Atomic cutover at 2026-11-18T06:53:42Z to `/opt/tracker-v1/releases/1.2.8-ec868f9d`.
- Prior `current` and rollback target `/opt/tracker-v1/releases/1.2.7-6030f98e`. Rollback was unused. Before promotion, the running native Tracker, Observatory, and Web versions were 1.2.6, 1.2.6, and 1.2.7, respectively. A rollback followed by a native restart would execute the 1.2.7 binary from the prior directory and start a new registry.
- Protected backup `/root/tracker-128-backup-ec868f9d` includes the previous release, configuration and copies of the two databases. Both copies passed `PRAGMA quick_check`. All 9 files matched the backup manifest, with SHA-256 `55e1bcd92a64440ed08f3c445f62e9992f575c8440168d81529fc7090feff55d`.
- Restarted `tracker-v1.service`, `tracker-observatory.service`, and `tracker-web.service`. The running executables matched the new manifest. Nginx kept its process.
- The native restart reset the volatile registry. It held 636,911 peer registrations before cutover. The new instance reported 618 registrations when origin checks passed at 2026-11-18T06:53:45Z.
