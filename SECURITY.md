# Security

Please do not publish a vulnerability, exploit, credentials, private source configuration, peer addresses or resource identifiers in a public issue.

If the repository's GitHub Security tab offers **Report a vulnerability**, use that private reporting form. Its availability depends on the repository owner enabling private vulnerability reporting. If the form is not available, no private reporting channel is currently specified here; do not assume that a public issue or another address is a confidential channel.

A useful private report describes the affected revision, conditions, impact, minimal reproduction, and any suggested mitigation. Use synthetic hashes and loopback-only fixtures. Do not test a public production service or third-party tracker under load.

The project does not promise response times, anonymity or immunity from legal obligations. Deployment operators remain responsible for network exposure, dependencies, secrets and access controls.
